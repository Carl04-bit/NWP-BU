# Running a Simple WRF Simulation

This guide explains how to set up your environment, prepare your test case, and run a simulation using the centralized WRF/WPS installation. To save space on the system, we will symlink (shortcut) the required executables and static data instead of copying the entire software directories.

## Step 1: Environment Setup

Before doing anything, you must load the WRF environment and set your memory limits to prevent segmentation faults. Run this in your terminal:

```bash
source /opt/WRF_GNU/setenv-wrf.sh
ulimit -s unlimited
```

*Tip: You can add these two lines to your `~/.bashrc` file to load them automatically when you log in.*

## Step 2: Set Up WPS and WRF Directories via Symlinks

To keep the centralized installation clean and save disk space, all simulations will be run inside a dedicated workspace in your home directory using symbolic links.

### 1. Link WPS Setup
```bash
# Create and enter your personal workspace directory for WPS
mkdir -p $HOME/wrf_workspace/my_test_case/WPS
cd $HOME/wrf_workspace/my_test_case/WPS

# Link WPS executables and utility scripts
ln -sf /opt/WRF_GNU/WPS-4.7.0/*.exe .
ln -sf /opt/WRF_GNU/WPS-4.7.0/link_grib.csh .

# Link WPS table directories (required by geogrid, ungrib, metgrid)
ln -sf /opt/WRF_GNU/WPS-4.7.0/geogrid .
ln -sf /opt/WRF_GNU/WPS-4.7.0/ungrib .
ln -sf /opt/WRF_GNU/WPS-4.7.0/metgrid .

# Copy the namelist (must be copied so you can edit it!)
cp /opt/WRF_GNU/WPS-4.7.0/namelist.wps .
```

### 2. Link WRF Setup
```bash
# Create the WRF run directory
mkdir -p $HOME/wrf_workspace/my_test_case/WRF_run
cd $HOME/wrf_workspace/my_test_case/WRF_run

# Link ALL files from the central WRF run directory 
# (This brings in wrf.exe, real.exe, and all necessary .TBL and lookup data files)
ln -sf /opt/WRF_GNU/WRF-4.8.0/run/* .

# Remove the linked namelist.input and replace it with a physical copy
rm namelist.input
cp /opt/WRF_GNU/WRF-4.8.0/test/em_real/namelist.input .
```

### 3. Apply the Robustness Patch
Execute the centralized system patch tool (`patch_wrf`) on both folders to automatically hardcode WPS table paths and link all required trace gas and aerosol physics files.
```bash
# Patches namelist.wps to prevent symlink MPI_ABORT errors
patch_wrf $HOME/wrf_workspace/my_test_case/WPS

# Exhaustively links CAM*, aerosol*, and RRTMG* files for real.exe
patch_wrf $HOME/wrf_workspace/my_test_case/WRF_run
```

## Step 3: Run WPS (Preprocessing)

WPS prepares your domain and meteorological data for WRF.

1. **Navigate to your local WPS folder:**
   ```bash
   cd $HOME/wrf_workspace/my_test_case/WPS
   ```

2. **Configure Domain:**
   Open `namelist.wps` and configure your domain parameters. Ensure the `geog_data_path` points to `/opt/WRF_GNU/WPS_GEOG`. *(Note: `opt_geogrid_tbl_path` and `opt_metgrid_tbl_path` have already been injected by `patch_wrf`).*

3. **Run Geogrid:** (Defines the model domains)
   ```bash
   ./geogrid.exe
   ```

4. **Link Meteorological Data:** (Replace the path with the location of your GFS/FNL GRIB data)
   ```bash
   ./link_grib.csh /path/to/your/met/data/*
   ```

5. **Run Ungrib:** (Extracts the meteorological fields)
   ```bash
   ln -sf ungrib/Variable_Tables/Vtable.GFS Vtable  # Assuming GFS data
   ./ungrib.exe
   ```

6. **Run Metgrid:** (Interpolates meteorological data to your domains)
   ```bash
   ./metgrid.exe
   ```
   *You should see `met_em.d0X.*` files generated upon success.*

## Step 4: Run WRF (Simulation)

WRF uses the output from WPS to perform the actual simulation.

1. **Navigate to your WRF run directory:**
   ```bash
   cd $HOME/wrf_workspace/my_test_case/WRF_run
   ```

2. **Link Metgrid Files:**
   Bring in the data generated by WPS:
   ```bash
   ln -sf ../WPS/met_em.d0* .
   ```

3. **Configure Simulation & Dynamic Stability:**
   Edit `namelist.input` to match the exact start/end dates and domain dimensions specified in your `namelist.wps`. To prevent CFL numerical instability during severe weather:
   * In `&domains`: Set `time_step` conservatively (e.g., `3 * dx` in km, such as `90` for a 27–30 km grid).
   * In `&dynamics`: Ensure `w_damping = 1` is set to safely absorb intense vertical updrafts.

4. **Run `real.exe`:** (Generates initial and boundary conditions)
   ```bash
   mpirun -np 4 ./real.exe
   ```
   *Check `rsl.error.0000` or `rsl.out.0000` to ensure it completed successfully without errors. You should see `wrfinput_d0*` and `wrfbdy_d01` generated.*

5. **Run `wrf.exe`:** (Executes the model)
   ```bash
   mpirun -np 4 ./wrf.exe
   ```
   *Note: WRF output files (`wrfout_*`) can grow to several gigabytes. Monitor your VM's disk space using the `df -h` command.*
